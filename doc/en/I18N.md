# I18N.md — Multi-language system

Memofun supports **Spanish (es, default)** and **English (en)** in the
interface. Each deck's content (questions/answers) does **not** go
through this system: it's generated in one language and stays in that
language, labelled in `decks/manifest.json`.

## How it works

- `assets/js/i18n.js` holds a `DICT.es` / `DICT.en` dictionary with the
  "core" keys (shared across the app: buttons, navigation) and exposes
  `App.i18n.register(dict, locale)` so each page can add its own.
- Each page has `strings.es.js` and `strings.en.js` that call
  `App.i18n.register({...}, 'es'|'en')` with their own keys, nested
  under a namespace (`home.*`, `study.*`, `settings.*`).
- `App.i18n.t(key)` looks up `es.<key>` or `en.<key>` depending on the
  active language (`App.i18n.locale()`), falling back to `es` if a key
  is missing in `en`.
- `App.i18n.apply(root)` walks `[data-i18n]`, `[data-i18n-aria]` and
  `[data-i18n-meta]` and fills in the matching text/attribute. Called
  automatically when each page loads.
- The active language is saved in `localStorage` (`memofun:locale`);
  if none is saved, it's detected from `navigator.language`.
  `settings/` has the buttons to change it.

## Parity rule

Any new UI text (button, message, instruction) must be added to
**both** `strings.es.js` and `strings.en.js` in the same change. `es`
is the source of truth unless stated otherwise.

## Adding a new key

1. Add it to the `es` block of the relevant `strings.<page>.es.js` (or
   `DICT.es.core` in `i18n.js` if it's shared app-wide).
2. Add the translation to `strings.<page>.en.js` (or `DICT.en.core`).
3. Use it with `data-i18n="namespace.key"` in HTML, or
   `App.i18n.t('namespace.key')` from JS.

## Adding a new language

1. Add its code to `SUPPORTED` and an entry in `BCP47` in
   `assets/js/i18n.js`.
2. Copy the `es` block of every `strings.*.js` in the repo and
   translate it.
3. Add the matching `<script src="strings.<language>.js">` to each
   `index.html`.
4. Add the language button in `settings/index.html` and its handler in
   `settings/app.js`.

None of this touches `tools/study/app.js` or `app.js` logic: they only
read `App.i18n.t()`, never a hardcoded string or language.
